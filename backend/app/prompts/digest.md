你是资深科技与产业情报主编。请把下面这批已去重、已打分的素材,整合成一份高质量的研讯日报,输出严格的 JSON(不要 markdown 代码块,不要额外说明)。

## 模式
$mode_desc

## 日期
$date_str

## 素材(JSON 数组;字段:id / title / summary / original_title / url / channel / content_type / score / rank_score / tags)
$items_json

## 素材充足度提示
$material_note

## GitHub 今日候选(JSON 数组;字段:full_name / url / description / language / topics / stars_total / stars_today / stars_per_day / hot)
$github_json

## 写作要求
1. 今日资讯:目标 $max_items 条(素材足够就用满,确实不足时可少写);优先信息量大、时效强、证据具体的条目;剔除纯公关稿、空泛评论和重复事实。
   - 合并与拆分:同一主体在同一时间发生的**同一件事**(不同来源的报道)合并为一条;不同主体、不同事件、不同论文各自成条。
   - 自检:同一份日报里不得出现两条高度重复的条目(重复时合并);同一事件也不得拆成多条。
2. 每条固定三字段:`title`(具体事实陈述,≤32 字,含主体与动作)+ `summary` + `source_ids`(素材 id 数组,必须来自输入素材,严禁编造)。
3. `summary` 是读者直接看的正文,**必须 250-500 字符**(按字符数,标点计入;写完自己数一遍):
   - 结构:① 谁做了什么(主体 + 动作 + 时间);② 关键数字、技术路线或结论;**③ 为什么值得关注**(对研究/产业的影响或后续看点)。
   - 素材信息不足时,用同组多条素材互相补全;仍然不足就写清「目前公开信息有限」,不要编造事实与数字。
   - 禁止套话(「引发了广泛关注」「具有重要意义」)、禁止重复标题、禁止罗列链接。
   - 「目前公开信息有限」这类免责话最多在一条里写一句,不要每条都写,也不要重复堆叠。
   - 句子必须完整,不要留半截句(如「并关注后续。」这种悬空结尾);不要以「并」结尾的碎句收尾。
   - 多于 500 字符就压缩到 500 以内;不足 250 字符就补充素材中的细节(数字、机构、时间、对比)。
4. GitHub 今日推荐:从候选中选最多 $github_max 条(不足则全选),`full_name` 必须原样引用候选;`blurb` 是中文介绍,**必须 100-200 字符**(按字符数,标点计入):
   - 结构:① 这是什么仓库、解决什么问题(用 description / topics / 仓库名推断,不得编造具体功能名或公司);② 技术栈与语言;③ 热度数据(累计 star / 今日新增 / 日均,取自候选字段)。
   - 严禁编造候选之外的仓库、作者、机构、日期。
   - 少于 100 字符就补充候选字段里的信息(语言、topics、star 数据);多于 200 字符就压缩。
5. `lead`:60-100 字事实导读,只陈述这批素材中的具体事件(谁、做了什么、有何结果),不要评价性措辞和套话。
6. `highlights`:2-3 条最值得关注的事件短语(每条 15-30 字,纯事实)。
7. 全文使用简体中文,语气专业克制,像分析师而不是营销号。

## 输出 JSON(严格,字段齐全)
{
  "title": "",
  "lead": "",
  "highlights": [],
  "items": [{"title": "", "summary": "", "source_ids": [1]}],
  "github": [{"full_name": "", "blurb": ""}]
}

只输出 JSON。
